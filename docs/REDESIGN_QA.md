# 주문 작업함 리디자인 검증

검증일: 2026-11-05. 사용자 선택 B(주문 작업함)를 반영한 로컬 프런트엔드와 기존 Azure 백엔드를 연결했다. 아래는 GitHub 게시 전에 수행한 로컬 검증 기록이다. 리디자인 UI는 Azure 공개 데모에 배포하지 않았다.

## 범위

- 흰 바탕·초록 강조색, 공통 탐색과 버튼, 고객 목록·상세, 모바일 목록 복귀.
- 데스크톱 1440×900, 모바일 390×844 화면 검토. 1024×768에서도 주문 작업함 가로 넘침 없음.
- 기존 API, AI 에이전트, 계산·장부 저장 로직은 변경하지 않았다.

## 기능 확인

실제 Azure API에 별도 작업공간을 생성하고 합성 예제만 사용했다.

| 항목 | 결과 |
|---|---|
| 로그인 없는 예제 진입 | 통과 |
| AI 처리 → 확인 질문 | 고객 9명·메시지 12건·입금 문자 7건 처리, 질문 4건 표시 |
| 검색·빈 결과 | 고객 검색, 결과 없음 안내, 검색 초기화 확인 |
| 모바일 상세 → 목록 | 선택했던 고객으로 키보드 초점 복원 |
| 모바일 메뉴 | 열기·Escape 닫기·메뉴 버튼 초점 복원 |
| 질문 답변 → 최종 승인 | 추천 답변 4건 반영 후 승인 대기·장부 확정 확인 |
| 확정 결과 | 주문 11줄, 입금 7건, 출고 8건·13박스, 환불 예정 36,000원 |
| CSV | 브라우저에서 택배 CSV 다운로드 성공, 데이터 8행 |
| 새로고침 | 작업공간 재연결 후 확정 출고 기록 유지 |
| 정답 대조 | 전체 24/24 일치 |
| 최종 페이지 콘솔 | 오류 0건 |

## 화면 검토

독립 검토에서 상단 보조 정보가 확인 질문을 화면 아래로 밀어낸다는 지적을 받았다. 자료·처리 현황을 한 줄로 접고, 질문이 있는 고객은 원문·금액 요약 다음에 질문을 배치했다. 재검토에서 해당 수정 항목은 해결됨으로 판정됐다. 모바일에서도 첫 질문의 선택지가 첫 화면 안에 들어온다.

README 이미지는 디자인 시안이 아닌 위 실행 중의 실제 화면이다. 합성 개인정보를 사용했으며 이미지에 캡처 출처를 기록했다.

## 검증 한계

- TypeScript 검사와 Vite 프로덕션 빌드, `git diff --check` 통과.
- 위 결과는 합성 예제 단일 실행이다. 실제 농가 효과·임의 입력 정확도·동시성·장애 복구를 입증하지 않는다.
- 이번 작업에서 백엔드 테스트 전체나 모든 오류 경로를 다시 실행하지 않았다.
- 이번 공개 범위는 소스·문서·로컬 화면 캡처다. 신규 UI의 Azure 배포는 포함하지 않는다.
